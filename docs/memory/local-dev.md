Local dev stack: pnpm runs via corepack, backend runs the working tree (restart it after edits), migrations are applied by hand.

- `pnpm` isn't on PATH; use `corepack pnpm test|lint|build` in `frontend/`.
- `docker compose up -d` mounts `./backend` into the backend container with `--reload`, so it runs whatever branch is checked out. `--reload` may not fire when the container runs in a VM (file events don't cross the bind mount); if an endpoint still behaves like the old code, `docker compose restart backend`. The frontend container serves a built bundle; rebuild it with `docker compose up -d --build frontend` to see frontend changes.
- Nothing runs Alembic on startup. After adding a migration, apply it to the local Postgres with `docker compose exec -T backend uv run alembic upgrade head`; otherwise endpoints that select the new column return 500.
- Backend tests build the schema with `create_all` on SQLite, so they never execute migrations. Add a dedicated migration test (see `backend/tests/test_migration_*.py`) and do an upgrade/downgrade round-trip on the local Postgres.
- Demo login for UI checks: `demo` / `demo` (seed with `scripts/seed-demo.sh`).
- To round-trip a migration on Postgres without touching the shared dev DB, use a throwaway container: `docker run -d --rm --name pg-check -p 127.0.0.1:55432:5432 -e POSTGRES_USER=t -e POSTGRES_PASSWORD=t -e POSTGRES_DB=t postgres:16`, then in `backend/` run `DATABASE_URL=postgresql+asyncpg://t:t@127.0.0.1:55432/t uv run --frozen alembic upgrade head` (then `downgrade -1`, `upgrade head`), and `docker stop pg-check`. This runs the whole chain from an empty DB.
- Exercises are managed in Settings (`SettingsPage.tsx` → `ExercisesSection`/`ExerciseForm`). There is no standalone exercises page.
- To check a frontend branch in a real browser against the running dev backend without rebuilding the frontend image: the backend publishes no host port, so forward one with a throwaway container (`docker run -d --rm --name trainlytics-verify-proxy --network trainlytics_default -p 127.0.0.1:18000:8000 alpine/socat TCP-LISTEN:8000,fork,reuseaddr TCP:backend:8000`), then run Vite with a config that imports `frontend/vite.config.ts` and overrides `server.proxy['/api']` to `http://127.0.0.1:18000`. That config must live in a file named `*.mts` (a `.ts` outside `frontend/` is loaded as CommonJS and fails on the ESM-only Tailwind plugin). Remove the container afterwards.
